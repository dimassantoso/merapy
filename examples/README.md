# Examples

## `sample_service/`

Generated by:

```bash
merapy init sample-service --package sample_service
cd sample-service
merapy add-module expense
```

The result is a working REST service exposing CRUD over an `expense` table.
The generated layout mirrors the clean-architecture flow described in the
project README:

```
sample-service/
├── pyproject.toml
├── Makefile
├── .env                              # USE_REST=true by default
├── main.py
├── alembic.ini
├── alembic/
└── sample_service/
    ├── configs/config.py             # load_service_configs(cfg)
    ├── internal/
    │   ├── service.py                # ServiceFactory impl
    │   └── modules/expense/
    │       ├── module.py
    │       ├── delivery/rest_handler.py
    │       ├── domain/
    │       ├── usecase/
    │       └── repository/
    └── pkg/shared/
        ├── domain/                   # SQLAlchemy Base + models
        ├── repository/repository.py  # RepoSQL UOW + @merapy:* markers
        └── usecase/usecase.py        # Usecase UOW + @merapy:* markers
```

## Run it

```bash
pip install -e ".[dev]"
docker run --rm -p 5432:5432 -e POSTGRES_PASSWORD=postgres postgres:16
make migration-create name=init
make migration
make run
# → curl http://localhost:8000/v1/expense/
```

## Swap the REST engine

```bash
REST_FRAMEWORK=litestar python main.py
```

Module handlers are unchanged — both adapters speak the same `RESTRouter`
Protocol.
